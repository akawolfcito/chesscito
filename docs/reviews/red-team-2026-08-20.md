## Dead Ends (user stuck)

### DE-1 · A featured card can bounce the player to the PATH with no explanation — **LATENT, not live**

**Where**: `exercises-screen.tsx` `requestTrainingContent`, the commercial branch:

```ts
if (result.action === "missing" || result.action === "locked") {
  …
  if (result.action === "locked" && result.openCheckout) { … }   // only `explicit_tap`
  else setExerciseDrawerOpen(true)                               // ← featured lands here
  return result
}
```

`openCheckout` is `source === "explicit_tap"`. A **featured** entry is therefore
refused *silently*: the player taps a card that advertises free Early Access and
is deposited on the exercise PATH with no message about what happened or why.

⛔ This is precisely the failure `lib/minigames/access.ts` documents as the
reason the access seam exists — *"una tarjeta que ofrece un juego que el router
después rechaza"* — reappearing through the **commercial** check rather than the
progression one. The `featured` flag deliberately bypasses only the progression
lock; nothing bypasses or explains the pass gate.

**Trigger**: any rotation entry whose challenge carries `access:
"training_pass"`.

**Measured, and it is NOT live today.** All twelve ids across the four shipped
rotations resolve to `access=base`:

```
early-access-1  rook-rail-two-roads / bishop-run-2 / queens-1       base
early-access-2  king-safe-1 / rook-rail-dead-end / bishop-run-3     base
early-access-3  queens-2 / king-safe-2 / rook-rail-rook-run         base
early-access-4  bishop-run-1 / queens-3 / king-safe-3               base
```

**Why it still matters**: rotation authoring is a code edit guarded by
`validateRotation`, and that validator checks *unknown / duplicate /
coming-soon* — **it does not check commercial access**. The day someone features
a pass-gated level, the surface breaks silently and no test fails.

## State Leaks (subtle bugs)

### SL-1 · `completionOriginRef` survives a jump to an exercise — **TRACED, not executed**

**Leaks from**: a featured mini-game → the exercise path.

`completionOriginRef` is cleared in exactly one place — `handleExitLabyrinth`.
It is **not** cleared by:

- `handleExerciseNavigate` (`exercises-screen.tsx:2177`) — dismisses the
  end-of-piece overlays and calls `goToExercise`, nothing else;
- `settleToPath()` inside `requestTrainingContent` — resets labyrinth state but
  leaves the ref alone.

And `automatic` **preserves** the origin by design (so a replay stays featured).

**Chain**:
1. Tap a featured card → origin = `featured_minigame`.
2. Open the PATH (the drawer is `open={exerciseDrawerOpen}`, *not* gated on
   `labyrinthMode`, so it is reachable from inside a mini-game) and tap an
   **exercise** node → `handleSelect` → `onNavigate(index)` →
   `handleExerciseNavigate`. **Origin still `featured_minigame`.**
3. Later enter a Special Training node through the contextual pin, which uses
   `requestTrainingContent(nextChallenge.id, "automatic")` → origin **preserved**.
4. Complete it → `handleLabyrinthContinue` sees `featured_minigame` → `router.push("/")`.

**Symptom**: a player who is standing in the exercise path is thrown back to the
Learn Home instead of continuing the path — the mirror image of the bug
`completionOriginRef` was introduced to fix.

⚠️ Traced through the code; the five-step repro was **not** executed. The one
uncertain link (drawer reachable during labyrinth mode) **was** verified.

**Smallest honest fix**: clear the ref wherever the player leaves lane content,
not only in `handleExitLabyrinth` — i.e. in `settleToPath()` and on exercise
navigation.

## Edge Cases (unhandled)

### EC-1 · The rail divider renders with zero mini-game tiles — **LIVE, measured**

**Where**: `hub-lite-scaffold.tsx`

```tsx
{miniGamesSlot ? <span className="hub-lite-path-rail-divider" … /> : null}
{miniGamesSlot}
```

Production always passes `miniGamesSlot={<MiniGamesSlot />}`. **A React element
is truthy even when the component returns `null`** — and `MiniGamesSlot` returns
`null` in two real situations:

- `!view` — bests are read in a mount effect, so **every first paint**;
- `view.cards.length === 0` — a rotation that resolves nothing.

Measured directly:

```
REDTEAM divider=RENDERED minigameTiles=0
```

**Symptom**: a separator floating to the right of the Exercises tile with
nothing to separate — a brief flash on every load, and **permanent** if a
rotation ever resolves empty.

⛔ **The existing unit test gives false confidence.** `hub-lite-scaffold.test.tsx`
covers this with `miniGamesSlot: undefined`, a value production never passes. It
is green and it is not testing the shipping condition.

**Smallest honest fix**: decide the divider from the rendered *content*, not
from the node's existence — e.g. let the section own its own leading separator,
or pass a boolean the container already knows.

## Verified OK

Checked adversarially and found solid:

- **`lib/minigames/access.ts`** — the seam is total, has no wallet/balance/Date
  read, and its `allowed:false` branch already exists in the type so a future
  denial is a compile error at every call site rather than a runtime surprise.
- **`deriveFeaturedCardState`** — pure and total; reads siblings from the
  *projected* lane, so a retired id in stored bests cannot fake progress.
- **`appendTrainingRows`** (two maps + a spread) and **`pathLayout`** (one `for`
  over `nodeCount`) — both O(n), both loop-free. Checked specifically because
  the founder asked whether the lane-separation change could be hanging the app:
  **it cannot**.
- **Quota exhausted + already-solved content** — `isExerciseReplayable` returns
  true for anything with `stars > 0`, so a finished exercise never becomes
  unreachable at the daily limit; and carril 2 is deliberately not quota-gated
  (the removed `isLabReplayable` is documented as a lock with no key).
- **Rotation reach** — only 3 of 13 challenges are featured, but the PATH lists
  every lane node for the selected piece, so the other 10 are reachable. Removing
  lane rows from the PATH *would* strand them; they are still there.
- **`consequenceMessage` surface mapping** — every rung still announces on both
  surfaces; only the exercise-path tail is dropped. Guarded in both bundles.
- **Welcome-gift signing dead end** — fixed this session (`9fff99f2`), both
  halves (modal + owner), tests proved red first.
