# UX Review Report — 2026-06-14

Adversarial visual/UX consistency audit of the Chesscito core loop (mobile-first
390px). 5 parallel auditors: Hub+nav, Arena, Coach, Exercises, Economy. Judged
against the project design system (CTA token families in `globals.css :root`,
candy/`.arena-result-*`/`.hub-hud-pill` class families). UI language = **English**
(`editorial.ts`). Findings only — no fixes applied here.

## Cross-cutting themes (most valuable to fix first)

### T1 — "on-chain" / web3 jargon leaks into user copy (HARD-RULE violation, multi-surface)
The promise-first / no-web3-jargon rule is broken in several shipped strings:
- `editorial.ts:1706` `mintSavedToast: "Saved on-chain · #{tokenId}"` (arena loss toast + coach viewer)
- `editorial.ts:1707` `viewNft: "View NFT"`
- `editorial.ts:1744` `viewOnCeloscan: "View on Celoscan"` (+ opens celoscan.io)
- `editorial.ts:154` `saveOnChainCta: "Save on-chain"`, `:642` `toastWait: "Confirming on-chain…"`
- `editorial.ts:2221` `victorySubline` uses "mint"
→ Replace with neutral reward language ("Saved · #N", "View receipt"/"View proof",
"Save", "Confirming…"). Legal pages excepted.

### T2 — Hardcoded English bypassing i18n (ES users see English)
- **Economy CRITICAL**: the entire `get-peones-sheet.tsx` copy is hardcoded (the
  primary buy-Peones surface) — ~15 strings not in `editorial.ts`.
- Hub: `tile-availability.ts:44-46` ("Next Xh"/"Tomorrow"), `hub-scaffold.tsx:358`
  ("Ask"/"PRO" Coach badge); ES catalog ships English `mateLabel:"Training"`,
  `coachLabel:"Coach"` (`es.ts:1614-1615,1667`).
- Coach: `coach-history.tsx:434` (`{credits} credits`), `:127`/`coach-game-client.tsx:457`
  (`{N} moves`).
- Exercises: `mission-panel-candy.tsx:368,374` (`+N STAR`, `STREAK`).

### T3 — Save tile hierarchy is inconsistent win vs loss vs viewer (NEW from F8)
- Win Save = `arena-result-primary-cta--treasure` (gold, ~92px, headline+body+ribbon, dominant).
- Loss/draw/resign Save = `arena-result-secondary-action arena-result-save-cta` (flat cream ~40px).
- Viewer = flat 4-tile row, Save has no dominance over Play Again/Share (`game-actions-bar.tsx:201-211`).
→ Same action, three visual weights. The money/collectible action should read
consistently. (Arena C1, Coach #3.)

### T4 — Save lifecycle + error copy diverge win vs loss (NEW from F8)
- Win: full-screen `VictoryClaiming`→`Success`/`Error` with hero, progress dots,
  cancelled/timeout differentiation, reassurance ("Your progress is safe").
- Loss: inline busy button + toast + bare "Couldn't save" rose retry row, no
  progress signal on slow Celo confirms. (Arena C2, M3, M4.)

### T5 — Touch targets below 44px (a11y; feeds the /exercises ~83 score)
- `.candy-tray-pill` = 38px (`globals.css:2151`) — mission peek, piece picker,
  drawer trigger, mission-sheet Save buttons.
- Retry chips ~22px (`arena-end-state.tsx:604-611`, PersistOverlay `:819-836`).
- Piece trigger icon-only 36px (`piece-picker-trigger.tsx:44`). Dock at 44px floor.

### T6 — 30s re-save cooldown trap (founder-found)
`arena-end-state.tsx` Save re-arms after success, but the contract `mintCooldown`
(30s, `VictoryNFTUpgradeable:117`) reverts an immediate re-save → generic
"Transaction failed", sometimes after the ERC20 approve. Pre-existing on the win
re-save path. **Fix: disable/hide Save after a successful tx** (see Recommended).

- No dead-ends/unreachable screens; locked tiles no-op cleanly; `?fresh=1` carried into Arena.
- Win-state popups share `VictoryPopupShell` (scrim/panel/close + 92dvh scroll guard) — genuinely consistent.

- Economy: `user_rejected` cancellation UX + PurchaseConfirm disabled-reason hints are exemplary.
- Exercises: strong i18n discipline elsewhere; "Tap your piece first" hint fixed a real iPhone dead-end.
- No MiniPay listing-safety copy violations.

## Summary
- Surfaces audited: 5 clusters (Hub+nav, Arena, Coach, Exercises, Economy)
- Critical: 4 | Major: 14 | Minor: 18
- Top recurring themes: T1 web3-jargon copy, T2 hardcoded-English i18n gaps,
  T3 Save-tile hierarchy, T4 Save-lifecycle divergence, T5 sub-44px touch targets,
  T6 30s re-save cooldown trap.

## Recommended fix order (high ROI → lower)
1. **T6 cooldown** (founder-requested, tiny): after a successful save, disable/hide
   the Save tile ("Saved ✓") instead of re-arming — kills the 30s revert friction
   on both win and loss paths.
2. **T1 jargon copy** (hard-rule, ~30min, copy-only): neutralize "on-chain"/"NFT"/
   "Celoscan"/"mint" in `editorial.ts`.
3. **Economy CRITICAL #1+#2**: stop leaking raw `errorReason`; move GetPeonesSheet
   copy into i18n.
4. **T5 touch targets**: bump `.candy-tray-pill` to 44px + retry chips.
5. **T3/T4 Save consistency** (larger): align loss Save tile weight + lifecycle with win.
